# neveshtar (نوشتار)

**آن‌طور بنویسید که پایان‌نامه نوشته می‌شود.** `neveshtar` ابزاری **آفلاین و قاعده‌محور** برای *سطح زبانی* (رجیستر) نثر علمی فارسی است. شکل‌های گفتاریِ راه‌یافته به پیش‌نویس را پیدا می‌کند
(`می‌خوام`، `مهمه`، `خیلی`، `رو`، `اینجوری`)، **هر تغییر را با دلیل و سطح اطمینان** نشان می‌دهد و بازنویسی را به‌صورت **تغییرِ ردیابی‌شده‌ی ورد** می‌نویسد تا یکی‌یکی بپذیرید یا رد کنید.
هم‌چنین قراردادهای رایج پایان‌نامه را می‌سنجد (اول‌شخص، احتیاط و قطعیت‌نما، کمیت‌نمای مبهم، آغاز تکراریِ جمله‌ها، جمله‌های بسیار بلند، ادعا بدون ارجاع) و **قالب‌های جای‌خالی** برای بخش‌ها چاپ می‌کند.
بدون ابر، بدون مدل، بدون شبکه، بدون وابستگی.

## چرا

پیش‌نویس اول معمولاً همان‌طور تایپ می‌شود که حرف می‌زنیم: `داره`، `میشه`، `اونو`، `بخاطر`. بعضی از این‌ها دقیقاً یک شکل نوشتاری دارند («دارد»، «می‌شود»، «آن را») و می‌شود خودکار اصلاحشان کرد.
بعضی به بافت بستگی دارند («ولی ← اما» سلیقه است؛ «بره» یا فعل است یا بره‌ی گوسفند) و باید فقط **پیشنهاد** بمانند. `neveshtar` این مرز را دیدنی نگه می‌دارد: هر تغییر یک سطح،
یک دلیل دوزبانه دارد و حالت `safe` (پیش‌فرض) فقط موارد بی‌ابهام را اعمال می‌کند. چون خروجی تغییر ردیابی‌شده است، استاد راهنما (یا خودتان فردا) می‌بیند دقیقاً چه جابه‌جا شده.

## استفاده

</div>

```sh
neveshtar chapter.docx                       # = neveshtar check
neveshtar check chapter.docx --json          # machine-readable: code, text, suggestion, confidence, reason
neveshtar check chapter.docx --html r.html   # self-contained diff report
neveshtar fix chapter.docx                   # chapter.neveshtar.docx, safe mode, Word tracked changes
neveshtar fix chapter.docx --mode balanced   # + the likely ones
neveshtar fix chapter.docx --clean           # no tracked changes
neveshtar scaffold method --lang fa          # fill-in-the-blank frame
neveshtar rules
```

## سطح‌های اطمینان

- **high**: یک شکل نوشتاری؛ اعمالش امن است.
- **medium**: بسیار محتمل، اما بافت تعیین می‌کند.
- **low**: سلیقه یا دو خوانش.

`--mode safe` فقط *high* را اعمال می‌کند؛ `balanced` *medium* را هم؛ `all` *low* و کدِ اختیاریِ N201 (`می‌باشد`، `گردید`، `جهت`) را. یافته‌های سبک (S) توصیه‌اند، چون قراردادها در دانشگاه‌ها فرق دارد
(بعضی «نگارنده» می‌خواهند، بعضی مجهول را می‌پذیرند).

## `fix` با فایل `.docx` چه می‌کند

متن **فقط در runهای ساده** ویرایش می‌شود؛ قلم و درشتی می‌ماند و جایگزین، قالب واژه‌ی خود را می‌گیرد. فیلدها (SEQ، PAGE)، tab، تصویر و پاراگراف‌هایی که پیش‌تر تغییر ردیابی‌شده دارند دست‌نخورده و گزارش می‌شوند.
نقل‌قول مستقیم (`«…»`)، کد و نشانی اینترنتی هرگز بازنویسی نمی‌شود، چون گفتار مصاحبه حق دارد محاوره‌ای باشد. در حالت ردیابی‌شده، «رد همه»ی ورد دقیقاً متن اصلی را برمی‌گرداند (این یک آزمون است).
فایل ورودی هرگز بازنویسی نمی‌شود.

## محدودیت‌ها (لطفاً بخوانید)

- **ابزار بازبینی است؛ نه نویسنده و نه ابزار فرار.** پایان‌نامه‌ی شما را نمی‌نویسد، محتوا تولید نمی‌کند و برای پنهان‌کردن متن ماشینی یا عبور از آشکارسازهای هوش مصنوعی ساخته نشده؛ درباره‌ی آشکارسازها هیچ ادعایی (نه مثبت، نه منفی) ندارم.
  کیفیت علمی، درستیِ ارجاع‌ها یا موافقت استاد با یک انتخاب زبانی را تضمین نمی‌کند.
- **قاعده‌محور یعنی فهرست ثابت.** حدود ۱٬۳۰۰ شکل گفتاری (بیشترشان صرف‌های فعلیِ تولیدشده و یک جدول دست‌نویس)، بدون تحلیل‌گر صرفی و بدون مدل بافت. شکل‌های ناشناخته علامت نمی‌خورند و شکلِ دوخوانشی فقط پیشنهاد است.
  آزمون دقتِ عددی ندارم؛ آزمون‌ها قاعده‌ها را می‌سنجند، نه فارسی را به‌طور کلی. گویش‌های محلی تقریباً غایب‌اند.
- **غلط‌یاب املایی و دستوری نیست.** املا، مطابقت و واژگان را نمی‌سنجد. لغزش‌های تایپی (نیم‌فاصله، ي/ك عربی) کار [payanlint](https://github.com/mrzroot/payanlint) است.
- **بررسی‌های سبک، قاعده‌ی فهرستی‌اند** (الهام‌گرفته از فراگفتمان Hyland)؛ «قطعیت‌نما» یک فهرست واژه است، نه فهمِ ادعا. S401 و S801 در همان جمله دنبال عدد یا «نام، سال» می‌گردند و ارجاع شماره‌ای را گاهی از دست می‌دهند.
- **هیچ خروجی را در Microsoft Word باز نکرده‌ام.** تغییرهای ردیابی‌شده از ساختار OOXML ساخته و با python-docx و خواندنِ دوباره‌ی XML بررسی شده‌اند (پذیرش همه و ردِ همه هر دو متن مورد انتظار را می‌دهند)؛ رفتار Word و Word مک استدلالی است، نه مشاهده‌شده.
- فقط متن اصلی (`word/document.xml`، با سلول‌های جدول) خوانده می‌شود؛ پانویس، سرصفحه، پاصفحه، یادداشت و کادر متن نه. فایل `.doc` را ابتدا با `.docx` ذخیره کنید.
